# Contributing

Use minimal fictional examples for bugs and tests. Do not submit participant
responses, real screenshots, real OCR text, CSV exports, browser profiles, API
keys, or sensitive file paths. Existing research data and fixtures stay private.

Describe the change, relevant tests, and remaining limitations. Preserve existing
model tolerances and test references. Changes to feature ordering, tokenizer
settings or model weights need explicit compatibility review. Keep runtime
processing local and user-controlled. Disclose AI assistance and reused code.

Run the asset-independent tests in README.md; model-dependent tests additionally
require authorized assets. Do not infer emotion accuracy from unit tests alone.
Contributions must be code you are authorized to share under the project license,
with applicable third-party notices preserved.
